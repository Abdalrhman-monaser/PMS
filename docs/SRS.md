# وثيقة متطلبات النظام المصغرة (Mini-SRS)
## نظام إدارة المشاريع والمهام (Project Management System - PMS)

**الإصدار**: 1.0 (Release Candidate - M6)  
**العام الجامعي**: 2026/2027  
**الحالة**: معتمد (Approved)

---

## 1. وصف المشكلة (Problem Description)
تواجه فرق التطوير والمؤسسات صعوبات مستمرة في متابعة تقدم المهام وتوزيع المسؤوليات بدقة، بالإضافة إلى غياب الشفافية في تتبع الإنجاز، مما يؤدي إلى:
- تشتت الاتصال وفقدان المواعيد النهائية للمشاريع.
- صعوبة تقييم أداء الأعضاء والتحكم في صلاحيات الوصول للبيانات الحساسة.
- غياب آلية نسخ احتياطي مركزية تضمن استمرارية الأعمال عند حدوث أخطاء تشغيلية.

---

## 2. الحل المقترح (Proposed Solution)
تطوير منصة ويب مركزية قائمة على بنية برمجية معيارية قابلة للصيانة والتوسع (Modular Architecture) تتيح:
- إدارة المشاريع والمهام من خلال دورة حياة واضحة تبدأ من الإسناد وحتى الإغلاق.
- مصفوفة تحكم في الوصول مبنية على الأدوار (RBAC) لضمان أمان البيانات.
- واجهات برمجة تطبيقات (REST APIs) محمية برموز وصول (Bearer Tokens).
- خطط نسخ احتياطي وتعافي من الكوارث مؤتمتة وموثوقة.

---

## 3. المستخدمون المستهدفون (Target Personas)

1. **المدير العام (System Administrator)**:
   - يمتلك الصلاحية الكاملة على لوحة التحكم، وإدارة حسابات المستخدمين، وضبط مصفوفة الصلاحيات، وإدارة النسخ الاحتياطي.
2. **مدير المشروع (Project Manager)**:
   - يتولى إنشاء المشاريع، وإسناد المهام، ومتابعة نسبة الإنجاز والتقارير الدورية.
3. **عضو الفريق (Team Member)**:
   - يستعرض المهام المسندة إليه، ويحدث حالتها (قيد التنفيذ / مكتملة)، ويطلع على الإشعارات.

---

## 4. نطاق النظام (System Scope)

### أ. ما يغطيه النظام (In Scope):
- المصادقة وإدارة الجلسات الآمنة وتشفير كلمات المرور (BCRYPT).
- إدارة المشاريع والمهام (CRUD operations).
- واجهات استعلام REST API للمهام الخارجية.
- أتمتة النسخ الاحتياطي لبيانات MySQL وضغطها دورياً.
- فحص الجودة الآلي وسير العمل (CI Actions).

### ب. خارج نطاق الإصدار الحالي (Out of Scope):
- بوابات الدفع الإلكتروني المباشر.
- المحادثات الفورية (Real-time WebSocket Chat).
- تطبيقات الهواتف الذكية الأصلية (Native Mobile Apps).

---

## 5. المتطلبات الوظيفية (Functional Requirements)

- **FR-01 (إدارة الحسابات والمصادقة)**: يجب أن يتيح النظام تسجيل الدخول، تسجيل الخروج الآمن، وتوليد جلسة جديدة مع تجديد المعرف تلقائياً.
- **FR-02 (إدارة المشاريع)**: إمكانية إنشاء وتعديل وحذف المشاريع وتحديد موعد التسليم النهائي والحالة العامة.
- **FR-03 (إدارة المهام وتتبعها)**: إمكانية إسناد المهام إلى مستخدمين محددين، وتعديل أولويتها، وتغيير حالتها (To Do, In Progress, Done).
- **FR-04 (الصلاحيات المقيدة)**: حجب الصفحات الإدارية عن غير المدراء وعرض كود المنع `403 Forbidden` عند محاولة الوصول غير المصرح.
- **FR-05 (واجهة REST API)**: توفير نقطة نهاية محمية `GET /api/tasks` لاسترجاع قائمة المهام بصيغة JSON عبر Bearer Token.
- **FR-06 (النسخ الاحتياطي)**: تنفيذ تفريغ لقاعدة البيانات MySQL بضغطة زر أو أمر مجدول وضغط المخرجات بصيغة `.sql.gz`.

---

## 6. المتطلبات غير الوظيفية (Non-Functional Requirements)

- **NFR-01 (الأمان - Security)**:
  - استخدام استعلامات PDO المجهزة (Prepared Statements) حصرًا لمنع هجمات SQL Injection.
  - تطبيق آليات الحماية ضد هجمات تثبيت الجلسات و CSRF.
- **NFR-02 (الأداء - Performance)**:
  - ألا يتجاوز زمن استجابة طلبات واجهات البرمجة والصفحات الأساسية ثانية واحدة تحت ظروف التشغيل العادية.
- **NFR-03 (الاعتمادية واستمرارية الأعمال - Reliability & Recovery)**:
  - إمكانية استعادة قاعدة البيانات من ملف النسخ الاحتياطي المضغوط في مدة لا تتجاوز 5 دقائق.
- **NFR-04 (قابلية الصيانة والشفافية - Maintainability & Transparency)**:
  - مطابقة الكود لمعايير PSR وفحص الأخطاء النحوية آلياً عبر GitHub Actions مع توثيق كافة التدخلات الهندسية في `AI_Log.md`.
